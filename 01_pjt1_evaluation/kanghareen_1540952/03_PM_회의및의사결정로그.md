# PM 회의 및 의사결정 로그

## 1. 주요 회의 안건

- 일반 보도블록과 점자블록 중 최종 점검 대상 선정
- 자율주행 방식 및 라인트레이싱 적용 범위
- Edge AI와 서버 AI 역할 분담
- MVP 파손 클래스 범위
- 위치 정보 수집 방법
- 관리자 웹 및 행정문서 기능 범위
- 6주 내 구현 가능한 우선순위

## 2. 주요 의사결정

### 결정 1. 점자블록 중심으로 주제 구체화

일반 보도블록 전체가 아닌 점자블록을 1차 점검 대상으로 선정했습니다.

### 결정 2. Edge AI는 데이터 선별에 집중

Edge AI가 파손 의심 여부를 빠르게 판단하고, 정상 영상은 폐기하며 파손 후보만 서버로 전송하도록 역할을 정의했습니다.

### 결정 3. 서버는 정밀 분석과 관리 기능 담당

서버는 파손 정도, 위치 중복 여부, 보수 필요성을 분석하고 관리자 웹 및 문서 생성 기능을 담당합니다.

### 결정 4. AI가 최종 보수 여부를 확정하지 않음

AI 결과는 `보수 필수 후보`, `보수 확인 필요`, `경과 관찰` 등 의사결정 지원 정보로 제공하고 최종 판단은 담당자가 수행하도록 기획했습니다.

### 결정 5. 행정문서는 완성본이 아닌 초안 제공

위치·이미지·파손 결과가 자동 입력된 점검 결과서와 보수 검토 신청서 초안을 생성하도록 범위를 조정했습니다.

## 3. 컨설턴트 검토 질문

1. 점자블록 직접 라인트레이싱과 사전 지정 경로 주행 중 어느 방식이 현실적인가?
2. Edge에서는 파손 유무, 서버에서는 파손 정도를 분석하는 구조가 적절한가?
3. MVP에서 파손 유형을 세분화할지 파손 유무만 판단할지?
4. 일반 GPS와 엔코더·IMU로 위치 정확도를 확보할 수 있는가?
5. 행정문서 초안 생성 기능의 적절한 범위는 어디까지인가?
6. 6주 내 모든 기능을 구현하려면 어떤 기능을 우선해야 하는가?

## 4. PM 진행 방식

- 회의 전 안건과 질문을 문서화했습니다.
- 팀원의 하드웨어·AI 의견을 기획서에 반영했습니다.
- 회의 후 결정사항을 기능과 일정에 반영했습니다.
- 불확실한 기능은 MVP와 향후 확장으로 구분했습니다.
