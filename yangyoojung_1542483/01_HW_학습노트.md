# 01. 임베디드 하드웨어 학습노트

## 0. 전체 그림

임베디드 시스템은 특정한 일을 수행하기 위해 기계 안에 넣는 작은 컴퓨터 시스템

예시는 로봇청소기, 자동차 내비게이션, 키오스크, 드론, 스마트워치 등

- 일반적인 동작 순서

```text
카메라 ──────→ 앞에 무엇이 있는지 확인
초음파센서 ──→ 물체까지의 거리 확인
IMU ─────────→ 충격과 기울기 확인
GPS ─────────→ 현재 위치 확인
                       ↓
               젯슨 오린 나노
                       ↓
         ┌─────────────┴─────────────┐
         ↓                           ↓
   모터와 조향 제어            서버에 정보 전송
```

---

## 1. 가장 먼저 알아야 하는 전기 기초

### 1.1 전압

전압은 전기를 밀어주는 힘과 비슷한 개념임.

물길에 비유하면 물을 밀어내는 수압에 해당함.

- 3.3V는 3.3볼트 전압
- 5V는 5볼트 전압
- 12V는 12볼트 전압

전자부품마다 사용할 수 있는 전압이 정해져 있음.

3.3V까지만 받을 수 있는 핀에 5V를 넣으면 고장 날 수 있음.

### 1.2 전류

전류는 실제로 흐르는 전기의 양과 비슷한 개념임.

물길에 비유하면 일정 시간 동안 흐르는 물의 양에 해당함.

모터는 센서보다 많은 전류를 사용함.

따라서 모터를 컴퓨터 보드의 신호 핀에 직접 연결하면 안 됨.

### 1.3 GND

GND는 전압을 비교할 때 기준이 되는 지점임.

서로 통신하는 장치들이 같은 기준을 사용하도록 GND 연결이 필요함.

예시는 라즈베리파이와 외부 전원을 사용하는 서보모터 사이의 GND 연결임.

```text
라즈베리파이 GND ─── 외부 전원 GND ─── 서보모터 GND
```

이를 공통 접지라고 부름.

### 1.4 입력과 출력

입력은 컴퓨터가 외부 정보를 받는 것임.

출력은 컴퓨터가 외부 장치에 명령이나 정보를 보내는 것임.

| 구분 | 예시 |
| --- | --- |
| 입력 | 터치센서, 온습도센서, 초음파센서, 카메라, GPS, IMU |
| 출력 | LCD, LED, 부저, 서보모터, 바퀴 모터 |

### 1.5 디지털과 아날로그

디지털 신호는 보통 켜짐과 꺼짐처럼 두 상태를 사용함.

```text
LOW  = 0 = 꺼짐
HIGH = 1 = 켜짐
```

아날로그 신호는 밝기나 온도처럼 연속적인 값을 사용함.

라즈베리파이와 젯슨의 GPIO에는 일반적인 아날로그 입력 기능이 없음.

아날로그 센서를 사용하려면 ADC라는 변환 장치가 필요함.

ADC는 아날로그 값을 컴퓨터가 이해할 수 있는 숫자로 바꾸는 장치임.

## 2. 작은 컴퓨터의 종류

### 2.1 MCU

MCU는 센서와 모터를 빠르고 일정하게 제어하는 작은 제어용 컴퓨터임.

대표적인 제품은 Arduino, ESP32, STM32임.

- 전원을 켜면 미리 작성한 프로그램을 바로 실행함
- 센서 읽기와 모터 제어에 적합함
- 가격과 전력 소비가 비교적 낮음
- 큰 AI 모델이나 일반 PC 프로그램 실행에는 적합하지 않음

### 2.2 SBC

SBC는 한 장의 보드로 만든 소형 컴퓨터임.

대표적인 제품은 Raspberry Pi와 NVIDIA Jetson임.

- Linux 운영체제 사용
- Python과 C++ 프로그램 실행
- 모니터, 키보드, 마우스, 카메라 연결 가능
- 인터넷과 서버 통신 가능
- 여러 프로그램을 동시에 실행 가능

### 2.3 실제 로봇의 역할 분담

큰 로봇에서는 AI 처리와 모터 제어를 서로 다른 보드가 담당하기도 함.

```text
젯슨 오린 나노
  └─ 카메라 처리, YOLO 실행, 주행 판단

Arduino 또는 STM32
  └─ 모터 제어, 센서 확인, 긴급 정지
```

젯슨이 두뇌 역할, MCU가 손발을 빠르게 움직이는 역할에 가까움.

## 3. Raspberry Pi 5

### 3.1 라즈베리파이 5란

라즈베리파이 5는 손바닥 크기의 작은 컴퓨터임.

일반 컴퓨터처럼 운영체제를 설치하고 프로그램을 실행할 수 있음.

동시에 GPIO 핀을 이용해 센서, LED, LCD 같은 전자부품도 제어함.

### 3.2 할 수 있는 일

- Python 공부와 프로그램 실행
- 센서값 수집
- LCD에 글자 출력
- 카메라 영상 확인
- 간단한 웹 서버 실행
- 다른 컴퓨터와 네트워크 통신
- 가벼운 영상 처리와 AI 실행

### 3.3 주요 부분

| 부분 | 쉬운 설명 |
| --- | --- |
| CPU | 프로그램의 일반 계산 담당 |
| RAM | 실행 중인 프로그램과 데이터를 잠시 보관 |
| microSD | 운영체제와 파일 저장 |
| USB | 키보드, 마우스, 카메라 등을 연결 |
| HDMI | 모니터 연결 |
| Ethernet | 유선 네트워크 연결 |
| Wi-Fi | 무선 네트워크 연결 |
| GPIO | 센서와 전자부품 연결 |

라즈베리파이 5는 2.4GHz 쿼드코어 Arm Cortex-A76 CPU와 40핀 GPIO를 제공함.

안정적인 사용을 위해 충분한 USB-C 전원과 냉각 장치 사용을 권장함.

### 3.4 GPIO

GPIO는 프로그램으로 입력 또는 출력을 제어할 수 있는 핀임.

예시는 다음과 같음.

```text
터치센서가 눌렸는지 읽기  → 입력
LED 켜기                   → 출력
서보모터에 제어 신호 보내기 → 출력
```

라즈베리파이의 GPIO 신호는 3.3V 기준임.

GPIO에 5V 신호를 직접 입력하면 보드가 손상될 수 있음.

핀 번호에는 물리적인 위치 번호와 GPIO 이름 번호가 있으므로 코드와 배선에서 같은 기준 사용이 필요함.

## 4. NVIDIA Jetson Orin Nano

### 4.1 젯슨 오린 나노란

젯슨 오린 나노는 NVIDIA에서 만든 소형 AI 컴퓨터임.

라즈베리파이와 비슷하게 Linux를 실행하지만 AI 계산에 강한 GPU를 포함함.

카메라 영상을 실시간으로 분석하거나 YOLO를 실행하는 작업에 적합함.

### 4.2 CPU와 GPU의 차이

CPU는 다양한 종류의 일을 순서대로 처리하는 데 강함.

GPU는 비슷한 계산을 매우 많이 동시에 수행하는 데 강함.

딥러닝은 같은 종류의 계산을 대량으로 수행하므로 GPU 사용 시 유리함.

```text
CPU = 여러 종류의 일을 능숙하게 처리하는 소수의 작업자
GPU = 같은 계산을 동시에 처리하는 많은 작업자
```

### 4.3 라즈베리파이 5와 비교

| 구분 | Raspberry Pi 5 | Jetson Orin Nano |
| --- | --- | --- |
| 주요 목적 | 센서, 서버, 교육, 일반 제어 | AI, 로봇, 영상 처리 |
| Linux 사용 | 가능함 | 가능함 |
| GPIO 사용 | 가능함 | 가능함 |
| AI 처리 | 가벼운 작업 중심 | GPU를 이용한 빠른 처리 |
| 전력과 발열 | 비교적 적음 | 상대적으로 많음 |
| 가격 | 상대적으로 낮음 | 상대적으로 높음 |

### 4.4 사용 시 주의점

- 안정적인 전원 공급 필요
- 팬과 방열판을 이용한 냉각 필요
- GPIO에 허용 전압보다 높은 신호 연결 금지
- 젯슨에 맞는 운영체제와 드라이버 설치 필요
- JetPack 버전과 Python 라이브러리의 호환성 확인 필요

## 5. JetPack 6.2

### 5.1 JetPack이란

JetPack은 젯슨을 사용하기 위해 NVIDIA가 제공하는 소프트웨어 묶음임.

컴퓨터에서 Windows를 설치한 뒤 여러 드라이버와 프로그램을 설치하는 것과 비슷함.

JetPack에는 다음 항목이 포함됨.

| 항목 | 쉬운 설명 |
| --- | --- |
| Jetson Linux | 젯슨 보드를 동작시키는 기본 운영체제 부분 |
| Ubuntu | 사용자가 프로그램을 실행하는 Linux 환경 |
| CUDA | NVIDIA GPU로 계산하기 위한 도구 |
| cuDNN | 딥러닝 계산을 빠르게 만드는 도구 |
| TensorRT | 학습된 AI 모델의 실행 속도를 높이는 도구 |
| VPI | 카메라 영상 처리용 도구 |
| 장치 드라이버 | 카메라와 하드웨어를 운영체제가 사용하도록 하는 프로그램 |

### 5.2 JetPack 6.2의 의미

JetPack 6.2는 JetPack의 특정 버전 이름임.

Jetson Orin Nano와 Orin NX에서 높은 성능을 사용할 수 있는 Super Mode가 추가된 버전임.

Super Mode 사용 시 성능이 높아질 수 있지만 전력 소비와 발열도 증가함.

따라서 충분한 전원과 냉각 장치가 필요함.

JetPack에는 6.2 이후의 보완 버전도 존재함.

프로젝트에서 정확히 6.2를 요구한다면 해당 버전 사용이 필요함.

버전 제한이 없다면 카메라, CUDA, PyTorch, YOLO 등과의 호환성을 확인한 후 버전 선택이 필요함.

### 5.3 TensorRT

TensorRT는 학습을 끝낸 AI 모델을 젯슨에서 빠르게 실행하도록 최적화하는 도구임.

```text
학습된 YOLO 모델
      ↓
TensorRT 최적화
      ↓
젯슨에서 더 빠른 객체 탐지
```

최적화 과정에서 속도, 정확도, 메모리 사용량 사이의 선택이 필요할 수 있음.

## 6. 오린카

### 6.1 오린카란

오린카는 보통 Jetson Orin Nano 또는 Orin NX를 두뇌로 사용하는 AI 자동차형 로봇을 의미함.

하나의 표준 제품 이름이라기보다 젯슨 오린 기반 자동차 키트를 부르는 표현으로 사용함.

제품마다 모터, 카메라, 제어 보드, 배터리 구성이 다를 수 있으므로 해당 제품의 설명서와 회로도 확인이 필요함.

### 6.2 일반적인 구성

| 구성 | 역할 |
| --- | --- |
| Jetson Orin Nano | 카메라 분석과 주행 판단 |
| RGB 또는 Depth 카메라 | 도로와 물체 촬영 |
| IMU | 기울기, 회전, 충격 측정 |
| 초음파센서 또는 LiDAR | 장애물까지의 거리 측정 |
| GPS | 현재 위치 측정 |
| MCU | 모터를 빠르고 일정하게 제어 |
| 모터 드라이버 | 모터에 필요한 큰 전류 공급 |
| DC 모터 | 바퀴 회전 |
| 서보모터 | 앞바퀴 방향 또는 카메라 방향 조절 |
| 배터리 | 전체 장치에 전력 공급 |

### 6.3 동작 예시

```text
1. 카메라로 앞쪽 촬영
2. YOLO로 사람과 장애물 탐지
3. 초음파센서로 장애물까지의 거리 확인
4. IMU로 차량의 기울기 확인
5. 젯슨이 정지 또는 회피 판단
6. MCU와 모터 드라이버에 명령 전달
7. GPS 위치와 위험 정보를 서버에 전송
```

### 6.4 모터 드라이버가 필요한 이유

젯슨과 라즈베리파이의 GPIO는 작은 제어 신호만 출력함.

바퀴 모터를 움직일 정도의 전류를 직접 공급하지 못함.

따라서 모터 드라이버가 중간에서 큰 전력을 제어함.

```text
젯슨의 작은 제어 신호
          ↓
     모터 드라이버
          ↓
배터리의 큰 전력으로 모터 구동
```

## 7. 서보모터 SG90

### 7.1 서보모터란

서보모터는 원하는 각도로 움직이는 모터임.

일반 DC 모터가 계속 회전하는 용도라면 서보모터는 특정 방향을 가리키는 용도에 적합함.

SG90은 작고 저렴한 교육용 서보모터임.

활용 예시는 자동차 조향, 카메라 방향 전환, 작은 로봇 팔 관절 등임.

### 7.2 선의 역할

제품마다 색상이 다를 수 있지만 일반적으로 다음과 같음.

| 선 색상 | 역할 |
| --- | --- |
| 갈색 또는 검정 | GND |
| 빨강 | 전원 |
| 주황 또는 노랑 | 제어 신호 |

### 7.3 PWM

SG90은 PWM이라는 반복적인 신호를 이용해 목표 각도를 전달함.

PWM은 매우 빠르게 켜고 끄는 신호임.

SG90에서는 한 번 켜져 있는 시간의 길이로 목표 각도를 전달함.

제품마다 정확한 각도 범위와 신호 범위가 다르므로 데이터시트 확인이 필요함.

### 7.4 전원 연결 주의

SG90을 라즈베리파이나 젯슨의 GPIO 전원으로 직접 구동하면 안 됨.

모터가 움직이는 순간 많은 전류를 사용해 보드가 재부팅되거나 고장 날 수 있음.

별도의 5V 전원 사용을 권장함.

```text
외부 5V 전원 ─── SG90 전원선
외부 전원 GND ── SG90 GND
보드 GND ─────── 외부 전원 GND
보드 GPIO ────── SG90 제어선
```

외부 전원과 보드의 GND를 연결하는 공통 접지 필요함.

## 8. I2C LCD

### 8.1 LCD란

LCD는 글자나 숫자를 화면에 표시하는 장치임.

16×2 LCD는 한 줄에 16글자씩 총 2줄을 표시하는 LCD임.

예시는 온도, 거리, 장치 상태 표시임.

```text
TEMP: 24 C
STATUS: SAFE
```

### 8.2 I2C란

I2C는 적은 수의 선으로 여러 장치를 연결하는 통신 방식임.

주요 선은 다음과 같음.

| 선 | 역할 |
| --- | --- |
| VCC | 전원 |
| GND | 접지 |
| SDA | 데이터 전달 |
| SCL | 통신 속도를 맞추는 시계 신호 |

각 I2C 장치는 자신만의 주소를 가짐.

주소는 아파트의 동·호수와 비슷한 역할임.

보드는 주소를 이용해 여러 장치 중 원하는 장치와 통신함.

```text
0x27 → LCD
0x68 → IMU
0x76 → 기압센서
```

실제 주소는 제품 설정에 따라 달라질 수 있음.

### 8.3 주의점

많은 I2C LCD 모듈은 5V를 사용함.

일부 모듈은 SDA와 SCL에도 5V가 걸릴 수 있음.

3.3V GPIO를 사용하는 라즈베리파이나 젯슨과 연결하기 전 전압 확인이 필요함.

필요한 경우 I2C 레벨 시프터를 사용함.

레벨 시프터는 5V 신호와 3.3V 신호 사이에서 전압을 안전하게 바꾸는 장치임.

## 9. 터치센서 TTP223B

### 9.1 터치센서란

TTP223B는 손가락이 닿았는지 감지하는 센서임.

스마트폰 화면처럼 손가락이 닿을 때 생기는 전기적인 변화를 감지함.

### 9.2 핀과 동작

| 핀 | 역할 |
| --- | --- |
| VCC | 전원 |
| GND | 접지 |
| OUT 또는 SIG | 터치 결과 출력 |

일반적인 동작은 다음과 같음.

```text
손가락이 닿지 않음 → LOW
손가락이 닿음      → HIGH
```

활용 예시는 장치 시작 버튼, LCD 화면 변경, 조명 켜기 등임.

모듈 설정에 따라 손을 대는 동안만 켜지는 방식과 한 번 누를 때마다 상태가 바뀌는 방식 사용 가능함.

## 10. 온습도센서 DHT11

### 10.1 DHT11이란

DHT11은 주변의 온도와 습도를 측정하는 저가형 센서임.

학습과 간단한 실내 환경 확인에 적합함.

### 10.2 측정값

- 온도
- 상대습도

상대습도는 현재 공기에 포함된 수증기의 정도를 백분율로 표현한 값임.

### 10.3 핀

모듈 형태에서는 보통 다음 핀을 사용함.

| 핀 | 역할 |
| --- | --- |
| VCC | 전원 |
| DATA | 측정값 전달 |
| GND | 접지 |

DHT11은 I2C 센서가 아님.

하나의 데이터선을 정해진 시간 규칙에 맞춰 사용하는 센서임.

직접 통신 규칙을 만드는 것보다 검증된 Python 라이브러리 사용을 권장함.

### 10.4 한계

- 정밀도가 높지 않음
- 빠르게 변하는 환경 측정에 부적합함
- 너무 자주 값을 요청하면 정상 측정이 어려울 수 있음

정확한 측정이 필요하면 DHT22나 SHT 계열 센서 사용을 고려함.

## 11. 초음파센서 HC-SR04

### 11.1 초음파센서란

HC-SR04는 소리를 보내고 돌아오는 시간을 측정해 물체까지의 거리를 구하는 센서임.

사람이 듣기 어려운 높은 주파수의 소리인 초음파 사용함.

### 11.2 핀

| 핀 | 역할 |
| --- | --- |
| VCC | 5V 전원 |
| TRIG | 초음파 발사 명령 |
| ECHO | 초음파가 돌아온 시간 전달 |
| GND | 접지 |

### 11.3 동작 과정

```text
1. 보드가 TRIG에 짧은 신호 전달
2. HC-SR04가 초음파 발사
3. 초음파가 물체에 부딪혀 반사
4. 센서가 돌아온 초음파 수신
5. ECHO 신호의 길이 측정
6. 왕복 시간을 이용해 거리 계산
```

소리가 물체까지 갔다가 돌아오므로 계산할 때 2로 나눔.

간단한 계산식은 다음과 같음.

```text
거리(cm) ≈ ECHO 시간(마이크로초) ÷ 58
```

### 11.4 반드시 알아야 하는 전압 문제

HC-SR04의 ECHO는 일반적으로 5V 신호를 출력함.

라즈베리파이와 젯슨의 3.3V GPIO에 직접 연결하면 손상될 수 있음.

ECHO와 GPIO 사이에 저항 분압 회로나 레벨 시프터 사용이 필요함.

```text
HC-SR04 ECHO 5V
       ↓
저항 분압 또는 레벨 시프터
       ↓
보드 GPIO 3.3V 이하
```

### 11.5 측정이 어려운 상황

- 천처럼 소리를 흡수하는 물체
- 표면이 비스듬해 소리가 다른 방향으로 반사되는 물체
- 너무 작거나 얇은 물체
- 너무 가깝거나 너무 먼 물체
- 여러 초음파센서를 동시에 사용해 신호가 섞이는 상황

## 12. RGB 카메라

RGB 카메라는 빨강, 초록, 파랑의 빛을 조합해 컬러 영상을 만드는 일반 카메라임.

사물의 색과 모양 확인에 적합함.

하지만 일반 RGB 카메라 한 대만으로 물체까지의 정확한 실제 거리 측정은 어려움.

거리가 필요하면 Depth Camera, Stereo Camera, LiDAR, 초음파센서 등의 추가 사용이 필요함.

## 13. YOLO

### 13.1 YOLO란

YOLO는 사진이나 영상에서 물체의 종류와 위치를 찾는 AI 모델임.

이름은 You Only Look Once의 약자임.

이미지를 한 번의 처리 과정으로 살펴보고 여러 물체를 빠르게 찾는다는 의미임.

### 13.2 결과

YOLO는 보통 다음 정보를 출력함.

| 결과 | 의미 |
| --- | --- |
| Class | 사람, 자동차, 신호등 같은 물체 종류 |
| Confidence | 예측을 얼마나 확신하는지 나타내는 값 |
| Bounding Box | 사진에서 물체가 있는 사각형 영역 |

예시는 다음과 같음.

```text
사람 / 신뢰도 91% / 화면 왼쪽 사각형
자동차 / 신뢰도 84% / 화면 중앙 사각형
```

### 13.3 학습과 추론

학습은 많은 사진과 정답을 보고 AI가 특징을 익히는 과정임.

추론은 학습을 끝낸 AI가 새로운 사진을 보고 결과를 내는 과정임.

오린카에서는 주로 젯슨에서 추론을 실행함.

```python
from ultralytics import YOLO

model = YOLO("모델파일.pt")
results = model("사진파일.jpg")
```

위 코드는 사용 방법을 보여주는 간단한 예시임.

실제 모델 이름과 설치 방법은 사용하는 YOLO 버전에 맞춰 확인이 필요함.

### 13.4 YOLO가 하지 못하는 일

YOLO의 일반적인 결과는 화면 안에서 물체가 있는 2차원 위치임.

실제 거리와 높이를 자동으로 정확하게 알려주는 것은 아님.

정확한 거리 측정을 위해 Depth Camera나 LiDAR 같은 센서와 함께 사용함.

## 14. IMU

### 14.1 IMU란

IMU는 물체의 움직임과 회전을 측정하는 센서임.

일반적으로 가속도계와 자이로스코프를 포함함.

### 14.2 가속도계

가속도계는 속도가 얼마나 빠르게 변하는지 측정함.

활용 예시는 다음과 같음.

- 충격 감지
- 흔들림 감지
- 급출발과 급정지 감지
- 중력 방향을 이용한 기울기 추정

오린카가 단차를 넘으면 위아래 방향인 Z축 값이 순간적으로 크게 변할 수 있음.

### 14.3 자이로스코프

자이로스코프는 물체가 얼마나 빠르게 회전하는지 측정함.

활용 예시는 회전, 방향 변화, 기울어지는 움직임 감지임.

### 14.4 Roll, Pitch, Yaw

| 이름 | 쉬운 설명 |
| --- | --- |
| Roll | 자동차가 좌우로 기우는 움직임 |
| Pitch | 자동차 앞부분이 위아래로 움직이는 회전 |
| Yaw | 자동차가 왼쪽이나 오른쪽으로 방향을 바꾸는 회전 |

```text
Roll  = 좌우 기울기
Pitch = 앞뒤 기울기
Yaw   = 진행 방향 회전
```

가속도계는 진동에 영향을 받고 자이로스코프는 시간이 지날수록 오차가 쌓일 수 있음.

두 센서의 장점을 합치는 센서 융합 사용이 필요함.

## 15. GPS

### 15.1 GPS란

GPS는 인공위성 신호를 이용해 지구 위의 현재 위치와 시간을 구하는 시스템임.

주요 결과는 위도, 경도, 고도, 시간임.

```text
위도: 37.5665
경도: 126.9780
고도: 42.7m
```

### 15.2 GPS 오차

일반 GPS에는 수 미터 수준의 오차가 생길 수 있음.

건물 사이, 터널, 실내, 나무가 많은 곳에서는 오차가 더 커질 수 있음.

GPS 고도는 짧은 높이 차이나 작은 단차를 측정하기에 정확하지 않음.

### 15.3 지오펜싱

지오펜싱은 특정 GPS 좌표 주변에 가상의 영역을 만드는 방식임.

예시는 위험 위치 반경 10m 안에 들어오면 경고를 표시하는 기능임.

```text
위험 지점 중심 좌표
        ↓
주변 반경 10m를 위험 구역으로 설정
```

### 15.4 반경 기반 중복 처리

같은 위험을 여러 번 측정해도 GPS 오차 때문에 좌표가 조금씩 달라질 수 있음.

기존 위험 지점의 반경 5m 안에 새 정보가 들어오면 같은 위험으로 처리하는 방식 사용 가능함.

반경 값은 GPS 정확도와 서비스 목적에 맞게 조정이 필요함.

### 15.5 데이터 상태와 만료

공사나 임시 장애물은 시간이 지나면 사라질 수 있음.

따라서 위험 정보에 상태와 유효기간을 함께 저장하는 것이 좋음.

```text
ACTIVE   → 현재 발견된 위험
VERIFIED → 다시 확인된 위험
EXPIRED  → 유효기간이 지난 위험
DELETE   → 삭제된 정보
```

TTL은 Time To Live의 약자로 데이터가 유효한 시간을 의미함.

## 16. 단차 측정 방법

단차는 도로나 바닥의 높이가 갑자기 달라지는 부분임.

GPS만으로 작은 단차의 높이를 측정하기는 어려움.

| 센서 | 역할 |
| --- | --- |
| RGB 카메라 | 단차처럼 보이는 모양 탐지 |
| Depth Camera | 화면 각 위치의 깊이 측정 |
| LiDAR | 물체와 바닥까지의 거리 측정 |
| 초음파센서 | 한 방향의 간단한 거리 측정 |
| IMU | 단차를 넘을 때 발생한 충격과 기울기 측정 |
| GPS | 단차가 발견된 대략적인 위치 저장 |

한 센서만 사용하는 것보다 여러 센서의 결과를 합치는 것이 안전함.

```text
카메라로 단차 후보 발견
        +
Depth Camera 또는 LiDAR로 높이 확인
        +
IMU로 실제 충격 확인
        +
GPS로 위치 저장
```

## 17. 하드웨어 통신 방식

### 17.1 GPIO

하나의 핀에서 HIGH 또는 LOW 신호를 읽거나 출력하는 단순한 방식임.

터치센서, 버튼, LED 등에 사용함.

### 17.2 PWM

신호를 빠르게 켜고 끄면서 켜져 있는 시간의 비율이나 길이를 조절하는 방식임.

서보모터 각도 제어와 LED 밝기 조절 등에 사용함.

### 17.3 I2C

SDA와 SCL 두 개의 신호선으로 여러 장치를 연결하는 방식임.

I2C LCD와 IMU 등에 사용함.

### 17.4 SPI

I2C보다 많은 신호선을 사용하지만 빠른 통신이 가능한 방식임.

빠른 센서, 디스플레이, 저장장치 등에 사용함.

### 17.5 UART

TX와 RX 선을 이용해 데이터를 주고받는 방식임.

GPS 모듈이나 MCU와의 통신에 자주 사용함.

송신 핀인 TX는 상대 장치의 수신 핀인 RX에 연결함.

```text
장치 A TX ─── 장치 B RX
장치 A RX ─── 장치 B TX
장치 A GND ── 장치 B GND
```

### 17.6 방식 비교

| 방식 | 주된 사용 |
| --- | --- |
| GPIO | 버튼, 터치센서, LED |
| PWM | 서보모터, LED 밝기 |
| I2C | LCD, IMU, 환경센서 |
| SPI | 고속 센서와 디스플레이 |
| UART | GPS, MCU, 시리얼 장치 |
| USB | 카메라, 키보드, 저장장치 |
| Ethernet·Wi-Fi | 다른 컴퓨터와 네트워크 통신 |

## 18. 소켓과 TCP 통신

### 18.1 네트워크 통신의 기본

네트워크 통신은 서로 떨어진 컴퓨터가 데이터를 주고받는 것임.

예시는 오린카가 측정한 위험 정보를 서버에 보내는 상황임.

```text
오린카의 젯슨 ── Wi-Fi 또는 Ethernet ── 서버
```

### 18.2 IP 주소

IP 주소는 네트워크에서 컴퓨터를 찾기 위한 주소임.

집 주소에 가까운 역할임.

예시는 `192.168.0.10`임.

### 18.3 Port

Port는 한 컴퓨터 안에서 어떤 프로그램과 통신할지 구분하는 번호임.

아파트 주소에서 방 번호와 비슷한 역할임.

예시는 `5000`, `8080` 등임.

```text
192.168.0.10:5000
└── IP 주소 ──┘ └Port┘
```

### 18.4 소켓

소켓은 프로그램이 네트워크 데이터를 주고받기 위해 사용하는 통신 창구임.

전화 통화에 비유하면 다음과 같음.

| 네트워크 | 전화 비유 |
| --- | --- |
| IP 주소 | 상대방의 건물 주소 |
| Port | 건물 안의 방 번호 |
| Socket | 실제 전화기 또는 통화 창구 |
| TCP 연결 | 상대방과 통화를 연결한 상태 |

### 18.5 서버와 클라이언트

서버는 특정 IP와 Port에서 연결을 기다리는 프로그램임.

클라이언트는 서버의 IP와 Port를 알고 먼저 연결하는 프로그램임.

오린카가 서버로 위험 정보를 보낸다면 일반적으로 다음 역할 사용함.

```text
오린카 = 클라이언트
데이터 저장 컴퓨터 = 서버
```

### 18.6 TCP

TCP는 상대방과 먼저 연결한 뒤 데이터를 안전하게 전달하는 통신 방식임.

주요 특징은 다음과 같음.

- 데이터 순서를 보장함
- 전달되지 않은 데이터의 재전송 수행함
- 오류 확인 수행함
- 연결 과정이 필요함
- UDP보다 안정적이지만 추가 처리와 지연이 발생할 수 있음

### 18.7 TCP의 중요한 특징

TCP는 편지 한 장씩 전달하는 방식이 아니라 끊임없이 이어지는 데이터 흐름을 전달하는 방식임.

보내는 쪽에서 한 번에 전송한 데이터가 받는 쪽에서도 똑같이 한 번에 도착한다는 보장이 없음.

따라서 메시지의 시작과 끝을 구분하는 규칙이 필요함.

대표적인 방식은 다음과 같음.

- 메시지 끝에 줄바꿈 문자 추가
- 데이터 길이를 먼저 전송
- 모든 메시지를 고정된 크기로 정의

예시는 줄바꿈 문자로 JSON 한 개의 끝을 표시하는 방식임.

```text
{"type":"obstacle","distance":1.2}\n
```

### 18.8 TCP 서버 예시

```python
import socket

server = socket.socket(socket.AF_INET, socket.SOCK_STREAM)
server.bind(("0.0.0.0", 5000))
server.listen()

connection, address = server.accept()
print("연결된 주소:", address)

data = connection.recv(1024)
print(data.decode())

connection.sendall(b"OK\n")
connection.close()
server.close()
```

`0.0.0.0`은 이 컴퓨터가 가진 모든 네트워크 연결에서 접속을 받겠다는 의미임.

### 18.9 TCP 클라이언트 예시

```python
import socket

client = socket.socket(socket.AF_INET, socket.SOCK_STREAM)
client.connect(("192.168.0.10", 5000))

client.sendall(b'{"type":"obstacle","distance":1.2}\n')
response = client.recv(1024)

print(response.decode())
client.close()
```

실제 서비스에서는 연결 끊김, 재연결, 시간 제한, 보안, 잘못된 데이터 처리도 필요함.

### 18.10 TCP와 UDP 비교

| 구분 | TCP | UDP |
| --- | --- | --- |
| 연결 | 먼저 연결함 | 별도 연결 과정 없음 |
| 순서 보장 | 보장함 | 보장하지 않음 |
| 재전송 | 수행함 | 기본적으로 수행하지 않음 |
| 속도와 지연 | 추가 처리가 있음 | 상대적으로 단순하고 빠름 |
| 적합한 예 | 위험 정보, 파일, 명령 | 실시간 영상, 간단한 반복 센서값 |

중요한 위험 정보를 확실하게 서버에 전달하려면 TCP 계열 통신이 이해하기 쉬운 선택임.

## 19. OSI 7 레이어 모델

### 19.1 OSI 7계층이란

OSI 7계층은 복잡한 네트워크 통신을 7개의 역할로 나누어 이해하는 모델임.

실제 데이터가 물리적으로 일곱 번 이동한다는 의미는 아님.

문제가 발생한 위치를 구분하고 통신 기술의 역할을 설명하기 위한 약속에 가까움.


### 19.2 7개 계층

| 계층 | 이름 | 쉬운 역할 | 관련 예시 |
| ---: | --- | --- | --- |
| 7 | 응용 계층 | 사용자가 사용하는 기능 | HTTP, MQTT, DNS |
| 6 | 표현 계층 | 데이터 형식과 암호화 | JSON, JPEG, 문자 인코딩 |
| 5 | 세션 계층 | 대화의 시작과 유지 관리 | 로그인 상태, 연결 유지 |
| 4 | 전송 계층 | 프로그램 사이의 전달 관리 | TCP, UDP, Port |
| 3 | 네트워크 계층 | 목적지 컴퓨터까지 길 찾기 | IP, Router |
| 2 | 데이터링크 계층 | 가까운 네트워크 장치까지 전달 | Ethernet, Wi-Fi, MAC 주소 |
| 1 | 물리 계층 | 전기 신호나 전파로 실제 전달 | LAN 케이블, 광케이블, 무선 전파 |

### 19.3 오린카 예시

오린카가 위험 정보를 서버에 전송하는 상황은 다음과 같음.

```text
7 응용 계층       위험 정보 전송 프로그램
6 표현 계층       정보를 JSON 형식으로 변환
5 세션 계층       연결 상태와 로그인 상태 관리
4 전송 계층       TCP와 Port를 이용해 전달
3 네트워크 계층   서버 IP 주소까지 경로 결정
2 데이터링크 계층 Wi-Fi 또는 Ethernet으로 주변 장치에 전달
1 물리 계층       무선 전파 또는 LAN 케이블로 실제 신호 전달
```

## 반드시 기억할 안전 원칙

> GPIO에 허용 전압보다 높은 신호를 넣지 않음

> 모터를 GPIO에 직접 연결하지 않음

> 모터에는 별도 전원과 모터 드라이버 사용함

> 서로 신호를 주고받는 장치의 GND 연결 필요함

> 전원을 연결하거나 배선을 바꾸기 전에 전압과 핀 위치 확인함

> HC-SR04의 ECHO 5V 신호를 3.3V GPIO에 직접 연결하지 않음

> I2C LCD의 SDA와 SCL 전압 확인 후 연결함
