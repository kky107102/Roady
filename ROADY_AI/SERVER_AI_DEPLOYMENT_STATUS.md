# 서버 AI 연결 현황

Jira: `S15P11A404-168`

## 현재 배포 모델

| 항목 | 값 |
|---|---|
| 모델 | YOLO26s-seg |
| 가중치 | `models/server/yolo26s_seg_multiclass_v2_best.pt` |
| 입력 | Edge가 전송한 점자블록 기준 ROI |
| 입력 크기 | 768 |
| 결과 정책 | 잠정 정책(`draft-1`), `advisory_only=true` |

## 모델 클래스와 서비스 표시

| ID | 학습 클래스 | 서비스 결과 | 처리 방식 |
|---:|---|---|---|
| 0 | `tactile_block` | 점자블록 | 파손 비율 계산의 기준 영역 |
| 1 | `missing` | 큰 결손·작은 결손 | 비율을 신뢰할 수 있을 때 15% 기준으로 후처리 구분 |
| 2 | `crack` | 균열 | 점자블록 내부의 유효 균열 Mask 분석 |
| 3 | `wear` | 마모 | 점자블록 내부의 유효 마모 Mask 분석 |

큰 결손과 작은 결손은 별도 학습 클래스가 아닙니다. 모델은 두 유형을 `missing`으로 분할하고,
개별 점자블록 대비 결손 비율을 계산할 수 있을 때만 15% 기준으로 구분합니다. 예상 블록 영역을
신뢰할 수 없으면 비율은 `null`로 유지하되 `LARGE_MISSING`, 점수 31, 보통 심각도를 적용합니다.

## 판단 보류

다음 조건에서는 판정값을 반환하면서 결과를 담당자 검토 대상으로 표시합니다.

- 점자블록을 찾지 못한 경우
- 개별 블록 분리가 불가능해 블록 그룹 단위로 분석한 경우
- 결손 비율 계산에 필요한 예상 블록 영역을 만들 수 없는 경우
- 점자블록 또는 파손 신뢰도가 기준보다 낮은 경우
- 파손 비율이 심각도 등급 경계에 가까운 경우
- 대표 프레임 품질이 검증되지 않은 경우
- Edge가 파손 후보 fallback ROI를 사용한 경우
- 모델 클래스 구성이 4클래스 계약과 다른 경우
- Edge에서는 파손 후보가 탐지됐지만 서버가 `missing`, `crack`, `wear`를 확정하지 못한 경우

계산할 수 없는 비율은 `0`으로 바꾸지 않고 `null`, `ratio_status=not_estimable`로 반환하지만,
탐지된 결손 자체는 보수적 기본값으로 파손 판정을 완료합니다.
현재 모든 분석 결과는 확정 행정 판단이 아닌 권고 결과이며 `advisory_only=true`입니다.
모델 전체 검증 지표인 `quality`는 참고 정보로만 제공하며 이미지별 판정과 검토 여부에는 사용하지 않습니다.

## 씽씽이 등 가림 물체 처리

씽씽이는 Edge에서 `damage_candidate`로 서버에 전달될 수 있지만, 서버의 파손 학습 클래스에는
포함되지 않습니다. 서버가 신뢰 가능한 파손 유형을 확정하지 못하면
`EDGE_SERVER_DISAGREEMENT` 사유와 함께 `review_required=true`를 반환합니다. 즉 정상이나 파손으로
임의 확정하지 않고 담당자 판단 보류로 연결합니다.

## API 연결

- `POST /analyze`: 원본 이미지, 분석 ROI 및 Edge 메타데이터 분석
- `GET /health/live`: 프로세스 생존 확인
- `GET /health/ready`: 모델 로딩·워밍업 완료 확인
- `GET /model-info`: 모델 파일명, SHA-256 및 클래스 매핑 확인

주요 응답 필드는 `units`, `summary`, `review_required`, `review_reasons`, `advisory_only`,
`artifacts`입니다. 기존 `regions.damage`와 최상위 `analysis` 필드는 백엔드 하위 호환을 위해
deprecated 상태로 유지합니다.

## 현재 한계와 후속 학습

- 실환경 데이터 라벨링과 유형별 성능 개선 학습은 계속 진행합니다.
- 새 모델은 동일한 4클래스 계약을 유지하고, 검증 후 가중치와 SHA-256을 함께 교체합니다.
- 실제 Edge 이벤트와 Spring 서버를 사용한 종단 간 통합 검증은 연결 환경에서 추가로 수행해야 합니다.
