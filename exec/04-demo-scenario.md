# Roady 시연 시나리오

## 1. 시연 개요

시연은 다음 순서로 진행한다.

```text
웹 로그인 및 운행 시작 명령
→ 로봇 운행
→ 점자블록 파손 탐지
→ 주행 완료 및 이미지 자동 업로드
→ Server AI 분석
→ 웹에서 파손 확인
→ 보수 요청
```

## 2. 시연 전 준비

### 2.1 서버 실행 확인

EC2에서 다음 컨테이너가 실행 중인지 확인한다.

```bash
docker compose ps
```

| 컨테이너 | 역할 | 확인 상태 |
| --- | --- | --- |
| `roady-mysql` | 서비스 데이터 저장 | `healthy` |
| `roady-redis` | 최신 로봇 위치와 AI 분석 큐 관리 | `healthy` |
| `roady-mqtt` | 로봇 telemetry와 명령 중계 | `healthy` |
| `roady-ai` | 점자블록 파손 이미지 분석 | `healthy` |
| `roady-backend` | 웹·로봇·AI 연동 API | `Up` |
| `roady-frontend` | 관리자 웹 서비스 | `Up` |

### 2.2 로봇 준비

1. 로봇과 Jetson Orin Nano의 전원을 켠다.
2. 점자블록 촬영 카메라와 주행 센서의 연결 상태를 확인한다.
3. Edge AI와 로봇 주행 프로그램을 실행한다.
4. 로봇이 MQTT broker에 연결되고 telemetry를 전송하는지 확인한다.
5. 로봇을 시연 주행 구간의 시작 위치에 배치한다.

## 3. 웹 로그인 및 운행 시작 명령

### 실행 순서

1. 브라우저에서 운영 도메인에 접속한다.
2. 로그인 화면의 `아이디`에 `admin`을 입력한다.
3. `비밀번호`에 시연 계정 비밀번호를 입력한다.
4. `로그인` 버튼을 클릭한다.
5. 왼쪽 사이드바에서 `로디 운행`을 클릭한다.
6. 로봇 목록에서 시연에 사용할 로봇의 `상세 보기`를 클릭한다.
7. 로봇 상세 화면에서 현재 위치, 배터리, 운행 상태 및 연결 상태를 확인한다.
8. `운행 시작` 버튼을 클릭하고 확인 창에서 명령을 전송한다.


### 확인 결과

- 웹에서 로봇 운행 시작 명령이 생성된다.
- 로봇이 명령을 수신하고 운행을 시작한다.

## 4. 로봇 운행

### 실행 순서

1. 로봇이 출발하는 모습을 보여준다.
2. 로봇이 점자블록을 따라 이동하는 모습을 보여준다.
3. 로봇의 현재 좌표, 배터리 및 운행 상태가 MQTT telemetry로 서버에 전달되는지 확인한다.

### 확인 결과

- 로봇이 정해진 점자블록 경로를 따라 주행한다.
- 로봇의 최신 위치가 Redis에 저장되고 웹 관제 화면에 반영된다.
- 실시간 상태가 WebSocket을 통해 웹 화면에 갱신된다.

## 5. 점자블록 파손 탐지

### 실행 순서

1. 로봇이 정상 점자블록과 파손 점자블록이 포함된 구간을 통과하도록 한다.
2. Edge AI가 카메라 영상에서 `tactile_block`과 파손 후보를 탐지한다.
3. 파손 이벤트가 확정되면 원본 이미지와 분석 대상 이미지를 로봇 내부에 저장한다.
4. 시연 화면 또는 로그에서 파손 후보 이벤트가 생성된 것을 확인한다.

### 확인 결과

- 정상 구간을 주행하면서 점자블록 영역을 인식한다.
- 균열, 결손 또는 마모가 있는 구간에서 파손 후보 이벤트가 생성된다.

## 6. 주행 완료 및 이미지 자동 업로드

### 실행 순서

1. 로봇이 지정된 주행 구간을 모두 통과하면 운행을 종료한다.
2. 로봇이 주행 중 생성한 파손 이벤트별 대표 이미지를 Spring API에 자동 업로드한다.
3. Spring 서버가 `damages`에 파손 사건을 생성하고 `damage_images`에 이미지를 저장한다.
4. 업로드 직후 파손 상태가 `AI_ANALYZING`으로 생성되는지 확인한다.

로봇이 호출하는 API:

```http
POST /api/damages
```

주요 전송 항목:

| 항목 | 내용 |
| --- | --- |
| `robotId` | 이미지를 촬영한 로봇 ID |
| `latitude`, `longitude` | 파손 탐지 위치 |
| `capturedAt` | 이미지 촬영 시각 |
| `images` | 파손 대표 이미지 |

### 확인 결과

- 사용자가 웹에서 직접 이미지를 등록하지 않아도 로봇이 자동 업로드한다.
- 파손 사건과 원본 이미지가 RDB에 저장된다.
- AI 분석 작업이 Redis queue에 등록된다.


## 7. Server AI 분석

### 처리 순서

1. Spring worker가 Redis queue에서 분석 작업을 가져온다.
2. 작업 상태를 `QUEUED`에서 `PROCESSING`으로 변경한다.
3. Spring이 저장된 이미지를 FastAPI AI 서버의 `POST /analyze`로 전송한다.
4. Server AI가 점자블록과 파손 영역을 픽셀 단위로 분할한다.
5. Server AI가 파손 여부, 파손 점수, 대표 파손 유형 및 보수 우선순위를 반환한다.
6. Spring이 분석 결과를 `damage_ai_analysis_results`에 저장한다.
7. 파손 사건 상태를 `AI_ANALYZED`로 변경한다.

주요 분석 결과:

| 항목 | 내용 |
| --- | --- |
| `damaged` | 파손 탐지 여부 |
| `damageScore` | 파손 픽셀을 기준으로 계산한 0~100점 점수 |
| `damageType` | `SMALL_MISSING`, `LARGE_MISSING`, `CRACK`, `WEAR` 중 대표 유형 |
| `repairRequired` | 보수 필요 여부 |
| `repairPriority` | `LOW`, `NORMAL`, `HIGH` 중 보수 우선순위 |
| `rawResult` | Mask, 픽셀 수 등 Server AI 상세 결과 JSON |

### 확인 결과

- AI 분석이 완료되면 분석 상태가 `SUCCESS`가 된다.
- 파손 사건 상태가 `AI_ANALYZING`에서 `AI_ANALYZED`로 변경된다.
- 상세 분석 결과가 `rawResult`에 보존된다.


## 8. 웹에서 파손 확인

### 8.1 탐지 검토 화면 이동

1. 앞 단계에서 로그인한 웹 화면으로 이동한다.
2. 왼쪽 사이드바에서 `탐지 검토`를 클릭한다.
3. `미확인` 탭 또는 최신순 목록에서 방금 생성된 파손 사건을 찾는다.

> **[사진 13 삽입]** 새 파손 사건이 표시된 탐지 검토 목록

### 8.2 AI 분석 결과 확인

1. 파손 사건 카드 또는 지도 마커를 클릭한다.
2. 오른쪽 사건 상세 패널에서 촬영 이미지와 탐지 위치를 확인한다.
3. `AI 판독 요약`에서 다음 정보를 설명한다.
   - 파손 여부
   - 파손 점수
   - 파손 유형
   - 보수 우선순위
   - AI 분석 상태
4. 촬영 이미지의 실제 파손 부위와 AI 분석 결과가 일치하는지 확인한다.
5. 관리자가 최종 파손 유형과 우선순위를 검토한다.

## 9. 보수 요청

### 9.1 관리자 판정

1. 파손 사건 상세 화면에서 `보수 필요`를 클릭한다.
2. AI 결과를 참고해 최종 우선순위를 선택한다.
3. 최종 파손 유형을 선택한다.
4. 필요한 경우 검토 비고를 입력한다.
5. 확인 버튼을 클릭해 관리자 판정을 저장한다.
6. 사건이 보수 요청 가능한 상태로 변경되는지 확인한다.

> **[사진 16 삽입]** 관리자 파손 판정 입력 화면

### 9.2 보수 담당자 요청

1. 왼쪽 사이드바에서 `보수 관리`를 클릭한다.
2. `요청 전` 상태 목록에서 방금 검토한 사건을 선택한다.
3. 사건 상세 화면에서 `보수 요청`을 클릭한다.
4. 보수 담당자를 선택한다.
5. 전달할 요청 메모를 입력한다.
6. `보수 요청하기`를 클릭하고 확인 창에서 요청을 확정한다.

### 확인 결과

- 관리자가 AI 분석 결과를 근거로 최종 판정한다.
- 지정한 보수 담당자에게 보수 요청이 등록된다.

> **[사진 18 삽입]** `요청 완료`로 변경된 보수 사건
