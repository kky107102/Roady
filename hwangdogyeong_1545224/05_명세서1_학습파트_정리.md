## 2. 온디바이스 AI

### 2.1 개념

온디바이스 AI는 AI 연산을 원격 클라우드 서버에만 의존하지 않고 데이터가 생성되는 장치 자체에서 수행하는 방식이다. GPU와 AI 가속 하드웨어가 소형화되고, TensorFlow Lite나 PyTorch 계열처럼 경량 장치에서 동작할 수 있는 프레임워크가 발전하면서 활용 범위가 넓어졌다.

### 2.2 클라우드 중심 처리의 한계

- 네트워크 상태에 따라 응답 시간이 달라진다.
- 모든 원본 데이터를 전송하면 네트워크 사용량이 증가한다.
- 영상과 같은 개인정보가 외부 서버에 저장될 수 있다.
- 통신이 끊기면 실시간 판단이 불가능해질 수 있다.
- 서버 저장·연산 비용이 커질 수 있다.

### 2.3 온디바이스 처리의 장점

- 센서 데이터가 생성된 위치에서 바로 처리되어 지연시간이 짧다.
- 통신 장애가 있어도 기본적인 판단을 계속할 수 있다.
- 필요한 이벤트만 전송하여 네트워크와 저장 공간을 절약할 수 있다.
- 원본 데이터의 외부 전송을 줄여 개인정보 노출 범위를 줄일 수 있다.
- 장치가 실시간으로 주변 상황에 반응하기 쉽다.

### 2.4 우리 프로젝트에 대입해 본 내용

우리 프로젝트에서는 Jetson Orin Nano가 온디바이스 AI 장치 역할을 한다. 로봇이 촬영한 정상 영상을 모두 서버로 보내지 않고, Edge 모델이 점자블록 파손 후보를 먼저 고르는 방식이다.

```text
카메라 원본 영상
  → Jetson에서 실시간 AI 추론
  → 정상 프레임은 순환 버퍼에서 폐기
  → 파손 후보만 대표 이미지·전후 영상으로 저장
  → 위치와 시간을 결합해 서버로 전송
```

즉, Edge AI의 목적은 서버 모델을 완전히 대체하는 것이 아니라 빠른 1차 선별과 데이터 절감이다.

## 3. AIoT 개념

AIoT(Artificial Intelligence of Things)는 AI와 IoT를 결합하여 센서 데이터를 수집하는 데서 끝나지 않고 데이터를 분석하고 상황에 맞는 판단과 제어까지 수행하는 시스템이다.

### 일반 IoT와 AIoT 비교

| 구분 | 일반 IoT | AIoT |
|---|---|---|
| 주요 목적 | 센서 데이터 수집·전송 | 데이터 분석·예측·자동 판단 |
| 처리 위치 | 서버 또는 단순 제어기 | Edge 장치와 클라우드/서버 |
| 동작 방식 | 정해진 규칙 중심 | AI 모델과 규칙을 함께 사용 |
| 출력 | 상태 표시와 원격 제어 | 이상 감지, 예측, 자율 동작 |

AIoT의 핵심 흐름은 다음과 같다.

```text
Sense → Connect → Analyze → Decide → Act
감지      연결       분석       판단      동작
```

우리 프로젝트에 대응해 보면 다음과 같다.

- **Sense:** 카메라, LiDAR, IMU, 엔코더, GPS가 데이터를 수집한다.
- **Connect:** ROS 2와 Wi-Fi/LTE를 통해 장치 및 서버가 통신한다.
- **Analyze:** Jetson과 서버 AI가 점자블록 및 파손 상태를 분석한다.
- **Decide:** 파손 이벤트 생성, 장애물 정지, 보수 검토 우선순위를 결정한다.
- **Act:** 로봇을 감속·정지시키고 이벤트를 저장·전송하며 관리자에게 알린다.

## 4. 클라우드 지능과 사물 지능화

명세서에서는 AIoT 구현 방식을 크게 클라우드 지능 활용과 사물 지능화로 구분한다.

### 4.1 클라우드 지능 활용

IoT 장치가 수집한 데이터를 서버로 전송하고 서버의 큰 저장 공간과 연산 자원으로 분석하는 방식이다.

적합한 작업:

- 대규모 데이터 저장과 통계
- 복잡하고 무거운 AI 모델 학습·추론
- 여러 로봇의 데이터를 합친 분석
- 관리자 웹과 행정문서 생성
- 장기간 파손 이력과 악화 추이 분석

### 4.2 사물 지능화

IoT 장치 자체에 AI 기능을 넣어 데이터가 발생하는 위치에서 분석하고 판단하는 방식이다. Edge Computing의 대표적인 형태이다.

적합한 작업:

- 카메라 프레임 실시간 추론
- 즉시 필요한 장애물 감지와 정지
- 정상 영상 폐기와 파손 후보 선별
- 통신 장애 중 로컬 동작
- 개인정보가 포함된 원본 데이터의 최소화

### 4.3 프로젝트의 하이브리드 구조

우리 프로젝트는 두 방식을 결합해야 한다.

| Edge/로봇 | 서버 |
|---|---|
| 실시간 파손 후보 탐지 | 고해상도 정밀 분석 |
| 연속 프레임 확인 | 파손 심각도와 우선순위 계산 |
| 정상 영상 자동 폐기 | 장기 데이터·처리 이력 저장 |
| 장애물 감지와 안전 동작 | 지도, 통계, 관리자 화면 제공 |
| 통신 장애 시 임시 저장 | 행정문서 초안 생성 |

Edge는 실시간성과 자율성에 강점이 있고, 서버는 큰 연산 능력과 통합 관리에 강점이 있다. 어느 한쪽에 모든 기능을 몰아넣기보다 응답시간, 네트워크, 개인정보, 모델 크기를 기준으로 역할을 나눈다.

## 5. 임베디드 시스템 이해

임베디드 시스템은 특정 목적을 수행하기 위해 하드웨어와 소프트웨어를 결합한 컴퓨터 시스템이다. 일반 PC와 달리 제한된 전력, 메모리, 저장 공간과 정해진 입출력 장치 안에서 안정적으로 동작해야 한다.

### 주요 특징

- 특정 기능과 목적에 맞게 설계된다.
- 센서 입력을 받고 액추에이터를 제어한다.
- 실시간 응답과 장시간 안정성이 중요하다.
- 하드웨어 자원이 제한적이다.
- 전원, 발열, 통신 장애를 고려해야 한다.

### 싱글보드 컴퓨터와 MCU

| 구분 | 싱글보드 컴퓨터(Jetson/Raspberry Pi) | MCU |
|---|---|---|
| 운영 환경 | Linux와 같은 운영체제 | 펌웨어 또는 RTOS |
| 강점 | AI, 영상, 네트워크, 복잡한 프로그램 | 빠르고 일정한 제어, 낮은 전력 |
| 프로젝트 역할 | AI 추론, ROS 2, 저장, 서버 통신 | 모터 제어, 센서 입력, watchdog, 긴급정지 |

Jetson에서 AI 프로그램이 멈추더라도 MCU가 모터를 안전하게 정지할 수 있도록 역할을 분리해야 한다.

## 6. GPIO와 하드웨어 인터페이스

GPIO(General Purpose Input/Output)는 컴퓨터 보드가 외부 장치와 디지털 신호를 주고받기 위한 핀이다.

### 입력과 출력

- **입력:** 버튼, 범퍼 센서, 디지털 센서의 상태를 읽는다.
- **출력:** LED, 릴레이, enable 신호 등을 제어한다.

GPIO 핀은 허용 전압과 전류가 작기 때문에 모터를 직접 연결하지 않는다. 모터처럼 큰 전류를 사용하는 장치는 모터 드라이버나 별도 제어 회로를 통해 구동해야 한다.

### 주요 통신 방식

- **I2C:** 두 개의 신호선을 여러 장치가 공유할 수 있다. 주소로 장치를 구분한다.
- **SPI:** 여러 신호선을 사용하지만 빠른 통신에 적합하다.
- **UART:** 송신과 수신 선을 이용한 직렬 통신으로 MCU, GPS 등에 사용된다.
- **USB:** 카메라, LiDAR와 같은 주변장치 연결에 사용된다.
- **Ethernet/Wi-Fi:** 로봇과 서버 또는 개발 PC 간 네트워크 연결에 사용된다.

장치를 연결할 때는 신호 전압, GND 공유, 통신 속도, 장치 주소와 핀 번호를 먼저 확인해야 한다.

## 7. 센서와 액추에이터

### 7.1 센서

센서는 실제 세계의 물리량을 전기적 또는 디지털 데이터로 바꾸는 장치이다.

프로젝트 센서의 예:

- 카메라: 빛을 이미지 데이터로 변환
- LiDAR: 각도별 거리 데이터 생성
- IMU: 가속도와 각속도 측정
- 엔코더: 바퀴 회전량 측정
- GPS/GNSS: 실외 위치 좌표 제공
- 범퍼 센서: 물체와의 접촉 상태 감지

센서 값은 항상 정확하지 않으므로 범위, 단위, 측정 주기, 노이즈, 결측값과 timestamp를 함께 확인해야 한다.

### 7.2 액추에이터

액추에이터는 컴퓨터의 제어 신호를 실제 세계의 물리적 동작으로 변환한다.

- DC 모터: 바퀴 회전과 이동
- 서보모터: 지정된 각도로 회전
- 솔레노이드: 전자기력으로 선형 동작
- 릴레이: 큰 전력의 회로를 켜고 끔
- LED/부저: 상태와 경고 출력

우리 프로젝트에서 가장 중요한 액추에이터는 좌우 주행 모터이다. AI가 내린 결과를 바로 모터 명령으로 쓰기보다 안전 상태 머신을 거쳐 제한된 속도와 방향으로 바꿔야 한다고 이해했다.

## 8. 제어 시스템의 기본 구조

```text
목표값 → 제어기 → 액추에이터 → 실제 동작
  ↑                               ↓
  └────────── 센서 피드백 ─────────┘
```

- **목표값:** 원하는 속도, 방향, 위치
- **제어기:** 목표와 현재 상태의 차이를 계산
- **액추에이터:** 모터를 실제로 움직임
- **센서 피드백:** 엔코더와 IMU가 현재 상태를 측정

피드백이 없는 개방 루프 방식은 같은 명령을 주어도 배터리 전압이나 노면 상태에 따라 결과가 달라질 수 있다. 엔코더와 IMU를 사용하는 폐쇄 루프 방식은 목표값과 현재값의 오차를 줄이도록 계속 제어할 수 있다.

## 9. 서보모터와 PWM

### 9.1 PWM 개념

PWM(Pulse Width Modulation)은 디지털 신호의 ON/OFF 시간을 빠르게 조절하여 모터 위치나 속도 등을 제어하는 방법이다.

- **주기:** 한 번의 신호가 반복되는 시간
- **주파수:** 1초 동안 신호가 반복되는 횟수
- **펄스 폭:** 한 주기 안에서 HIGH 상태를 유지하는 시간
- **Duty cycle:** 한 주기 중 HIGH 상태가 차지하는 비율

```text
Duty cycle(%) = HIGH 시간 / 전체 주기 × 100
```

서보모터는 일반적으로 펄스 폭을 각도 명령으로 해석한다. 다만 실제 최소·최대 펄스 폭과 회전 범위는 제품마다 다를 수 있으므로 데이터시트를 확인하고 물리적 한계 안에서 보정해야 한다.

### 9.2 피드백과 제어

서보모터 내부의 위치 센서는 현재 각도를 측정하고 제어 회로는 목표 각도와의 오차를 줄이도록 모터를 구동한다. 로봇 주행 모터도 엔코더 피드백을 사용하면 좌우 바퀴 속도를 일정하게 유지할 수 있다.

### 9.3 프로젝트 적용

- 카메라 또는 센서의 방향 조절 장치
- 조향 구조가 있는 로봇의 조향각 제어
- 엔코더 기반 좌우 바퀴 속도 보정
- 장애물 발견 시 목표 속도를 0으로 변경

## 10. 웹 서버와 장치 통신

명세서에서는 Raspberry Pi에 Flask 웹 서버를 두고 웹 화면과 하드웨어를 연결한다. 이 구조에서 학습한 핵심은 웹 페이지 자체보다 **장치 상태와 명령을 네트워크 API로 교환하는 방식**이다.

우리 프로젝트에는 다음과 같이 적용할 수 있다.

- 로봇이 현재 위치, 배터리, 주행 상태를 서버에 전송
- 서버가 점검 경로와 설정값을 로봇에 전달
- 파손 이벤트를 HTTP 또는 메시지 방식으로 업로드
- 전송 성공 여부를 확인하고 실패 시 재전송
- 관리자 명령을 검증한 뒤 로봇 상태 머신에 전달

웹 요청이 실패하거나 늦어져도 안전 정지는 로봇 내부에서 수행해야 한다. 원격 명령과 물리적 안전 제어를 같은 통신 경로에만 의존하지 않는다.

## 11. 우리 프로젝트에 대입한 전체 흐름

```text
[센서 계층]
카메라·LiDAR·IMU·엔코더·GPS
        ↓
[Edge/임베디드 계층]
Jetson AI 추론·ROS 2·이벤트 선별
MCU 모터 제어·watchdog·긴급정지
        ↓
[네트워크 계층]
Wi-Fi/LTE·재전송 큐·이벤트 업로드
        ↓
[서버 지능 계층]
정밀 AI 분석·데이터 저장·중복 병합
        ↓
[서비스 계층]
관리자 지도·처리 상태·행정문서 초안
```

## 12. 읽고 나서 이해한 내용

- 온디바이스 AI는 단순히 작은 모델을 실행하는 기술이 아니라 지연시간, 통신, 개인정보와 운영 비용을 함께 줄이기 위한 구조이다.
- AIoT는 센서 데이터 수집에서 끝나는 IoT에 AI 분석, 판단과 제어를 추가한다.
- Edge와 서버는 경쟁 관계가 아니라 실시간 처리와 정밀 분석을 나누는 협력 구조이다.
- Jetson과 Raspberry Pi 같은 싱글보드 컴퓨터는 복잡한 처리에 적합하고 MCU는 모터와 안전 제어에 적합하다.
- 센서 값에는 노이즈와 오차가 있으므로 하나의 측정값만으로 중요한 동작을 결정하지 않아야 한다.
- 액추에이터는 큰 전력을 사용하므로 GPIO에 직접 연결하지 않고 드라이버와 보호회로를 사용해야 한다.
- PWM의 주기, 펄스 폭과 Duty cycle을 이해해야 모터를 안전하고 정확하게 제어할 수 있다.
- 네트워크가 끊겨도 로봇의 정지와 기본 판단이 가능한 자율적인 Edge 구조가 필요하다.
