# 우리 프로젝트 AI 파트 정리

프로젝트 주제는 **점자블록 파손 점검 자율주행 AI 로봇 시스템**이다. AI 담당을 맡고 나서 기획서에 적힌 기능을 그대로 모델 하나로 만들 수 있는지부터 생각해 봤다. 정리해 보니 점자블록을 찾는 것, 파손을 찾는 것, 파손 정도를 계산하는 것, 같은 파손을 중복 등록하지 않는 것은 서로 다른 문제였다.

## 1. 문제를 AI 과제로 나누기

우리 프로젝트의 핵심은 로봇이 주행하면서 파손 후보만 골라 저장하고, 서버에서 한 번 더 확인하는 것이다. 막연하게 `파손 탐지 AI`라고 적기보다 내가 해야 할 일을 다음처럼 나눠 봤다.

1. **점자블록 영역 인식:** 화면에서 점자블록이 있는 위치를 찾는다.
2. **파손 후보 탐지:** 깨짐, 결손, 누락 등 이상이 있는 영역을 찾는다.
3. **상태 분류:** 정상/불량 또는 파손 유형을 분류한다.
4. **심각도 산정:** 파손 면적 비율, 경로 단절 여부 등을 계산한다.
5. **이벤트 선별:** 연속 프레임에서 같은 파손이 반복 확인될 때만 저장한다.
6. **중복 병합:** GPS, 경로 ID, 시간과 이미지 특징을 이용해 동일 위치의 반복 이벤트를 합친다.

MVP의 정답 범위는 법적 적합 여부의 자동 확정이 아니라 **점자블록 파손 의심 유무와 현장 확인 우선순위 제공**으로 제한한다.

## 2. 모델을 찾아보면서 비교한 것

### 2.1 이미지 분류

이미지 전체를 정상/불량으로 분류하는 방식이다. 구현이 단순하고 빠르지만 파손 위치를 표시하기 어렵고, 배경이나 촬영 구도에 의존할 위험이 있다. 데이터셋과 학습 파이프라인이 정상인지 확인하는 첫 베이스라인으로 사용한다.

### 2.2 객체 탐지

점자블록 또는 파손 부위를 bbox로 검출한다. 속도와 위치 정보의 균형이 좋아 Edge AI 1차 모델 후보로 적합하다. YOLO 계열의 작은 모델부터 시작해 정확도와 Jetson 추론 속도를 비교한다.

### 2.3 인스턴스/시맨틱 세그멘테이션

픽셀 단위 마스크를 예측한다. 파손 면적 비율과 경로 단절 정도를 계산하기 쉽고 작은 결손의 형태를 표현할 수 있지만, 라벨 준비와 추론 비용이 더 크다. 서버 정밀 분석 모델 또는 Edge 세그멘테이션 모델의 비교 후보로 둔다.

### 2.4 이상 탐지

정상 데이터의 분포를 학습하고 정상에서 벗어난 이미지를 찾는다. 라벨에 없는 새로운 파손을 찾는 장점이 있지만, 조명·그림자·오염도 이상으로 판단할 가능성이 크다. MVP의 주 모델보다는 알려지지 않은 실패 사례를 수집하는 보조 실험으로 적합하다.

## 3. 현재 생각한 모델 구조

```text
카메라 프레임
  -> 점자블록/파손 후보 Edge 모델
  -> 연속 프레임 확인 + 신뢰도 필터
  -> 대표 이미지와 전후 영상 저장
  -> 서버 정밀 모델
  -> 파손 면적·유형·우선순위 계산
  -> 담당자 검토
```

### Edge 단계

- 목표: 높은 Recall로 파손 후보를 놓치지 않으면서 실시간 처리
- 입력: 하향 카메라 프레임
- 출력: bbox 또는 mask, confidence, 정상/파손 후보
- 최적화: 입력 크기 축소, FP16, TensorRT, 프레임 샘플링
- 이벤트 조건: 단일 프레임이 아니라 최근 N개 프레임 중 K개 이상에서 확인

### 서버 단계

- 목표: 고해상도 crop을 사용해 Edge 오탐을 줄이고 심각도 산정
- 입력: 대표 이미지, 파손 전후 프레임, Edge 결과
- 출력: 파손 여부, 유형, 면적 비율, 검토 우선순위
- 원칙: 영상만으로 확정할 수 없는 재질·법적 규격은 `현장 확인 필요`로 남긴다.

## 4. 데이터 학습 시 주의할 점

### 데이터 누수 방지

연속 촬영된 유사 이미지가 train과 validation에 동시에 들어가면 성능이 과대평가된다. 파일 단위 무작위 분할보다 촬영일·지역·주행 구간을 기준으로 그룹 분할한다.

### 클래스와 환경 불균형

전체 정상/불량 수가 비슷해도 균열, 결손, 누락 등 세부 유형의 수는 다를 수 있다. 햇빛, 그림자, 비, 오염, 보행자 가림과 같은 환경별 분포도 확인한다.

### 도메인 차이

AI Hub 이미지는 실제 로봇 카메라의 높이, 각도, 렌즈, 흔들림과 다를 수 있다. 공개 데이터로 사전학습한 뒤 실제 카메라로 수집한 데이터를 validation/test에 포함하고, 마지막에 fine-tuning한다.

### 증강

- 사용 후보: 밝기/대비 변화, 약한 blur, noise, perspective, 부분 가림
- 주의: 실제 파손 모양을 훼손하는 과도한 crop이나 강한 기하 변환은 제한
- 검증셋과 테스트셋에는 증강을 적용하지 않음

## 5. 평가 지표

| 목적 | 지표 | 이유 |
|---|---|---|
| 파손 후보 탐지 | Recall | 위험 시설 미탐을 줄이는 것이 중요 |
| 탐지 정확도 | Precision, mAP50, mAP50-95 | 오탐과 위치 정확도 확인 |
| 세그멘테이션 | mIoU, Dice | 파손 면적과 경계 품질 평가 |
| 분류 | F1-score, confusion matrix | 클래스 불균형과 유형별 오류 확인 |
| Edge 적용 | FPS, p50/p95 latency | 실시간성과 지연 편차 확인 |
| 운영 | 시간당 이벤트 수, 중복률 | 담당자가 실제로 검토 가능한 양인지 확인 |

모델 지표만 높아도 서비스가 성공하는 것은 아니다. 그림자를 파손으로 보는 사례, 작은 균열을 놓치는 사례, 같은 위치가 반복 등록되는 사례를 별도 실패 목록으로 관리한다.

## 6. 학습·배포 파이프라인

1. AI Hub 원천 이미지와 JSON 라벨의 무결성을 점검한다.
2. 점자블록 데이터만 필터링하고 공통 내부 스키마로 변환한다.
3. 지역/촬영 단위로 train/validation/test를 분리한다.
4. 분류 또는 탐지 베이스라인을 학습한다.
5. 오류 분석 후 오탐 방지 데이터를 추가한다.
6. 최종 모델을 ONNX로 내보내고 결과가 원본 프레임워크와 일치하는지 확인한다.
7. TensorRT FP16 엔진으로 변환해 Jetson에서 속도와 메모리를 측정한다.
8. ROS 2 카메라 입력, 추론, 이벤트 저장 노드를 연결한다.

## 7. 공부하고 나서 정리된 점

- 기획서의 `Object Detection`만으로는 파손 면적을 정확히 계산하기 어렵기 때문에 세그멘테이션 비교가 필요하다.
- Edge는 최종 판정기가 아니라 후보 선별기이므로 Precision만 높이기보다 Recall과 이벤트 발생량을 함께 조정해야 한다.
- 공개 데이터의 성능보다 실제 로봇 카메라 환경에서의 성능이 중요하다.
- 프레임별 추론 결과를 그대로 서버에 보내지 않고, 연속 프레임 확인과 대표 이미지 선정 로직이 필요하다.
- 법적 적합성은 영상으로 확정하지 않고 AI 결과와 현장 확인 항목을 분리해야 한다.
